# Add a feature and plan its work

When you are done you will have a new feature on the **Features** page with a brief you checked, at least one of its uses planned into pieces of work the agents build, and you will know how to add more to it later.

**New feature**, **Plan this** and **+ Add something this feature should do** appear in a repository that plans by features; see [Planning by areas or by programs](knowledge-base/planning-modes).

The words on these screens are plain on purpose. Two of Fleet's own words appear once, small, after the plain one: a **piece of work** is what Fleet calls a slice, something you can try once it is done; a **plan** is what Fleet calls a PRD, what the agents build, written down first. What a feature, a use and a capability are is in [Features, uses and capabilities](knowledge-base/feature-areas).

## Add a feature

1. [you] **Press New feature.** It is at the top of the **Features** page, and **+ Add another feature** sits at the foot of the list. With no feature yet, the empty page offers it.
2. [you] **Describe the feature.** Give it a **Name**, then two or three sentences under **What should people be able to do, and who are they?** Say who uses it, what they need to get done, and how they do it today. Press **Draft the brief**.
3. [fleet] **Fleet drafts the brief.** It writes the summary, the problem, an example of a real person using it, what it is not, and a few uses. It asks a question only where your description leaves a real gap, at most two, on the same screen and in the [Cockpit](guides/daily/cockpit). You can leave the page while it works.
4. [you] **Review the brief.** This is how Fleet will describe the feature to everyone, people and agents alike. Click any text to change it, and add or remove a use under **What you can do with it**. **Ask for changes** sends Fleet a note and it drafts again. Nothing gets built yet.
5. [you] **Press Add feature.** You land back on the **Features** list, so adding several in a row is one click each.
6. [fleet] **Fleet saves it.** It writes the feature into your repository by itself, as one reviewed change. The feature then reads **Not started** and each use offers **Plan this**.

## Plan a use, or the whole feature

A use you add turns into work when you ask for it, or when you add it with **Add it and start planning**, which has Fleet start planning it the moment it lands. A use you add with plain **Add it** waits on the feature page like any other. **Plan this** beside a use that has nothing planned yet starts it. A use that already has part of its work planned, but still has a capability that is **Not built**, says **Plan what's missing** instead, and asks Fleet for the work those capabilities still need. A use whose capabilities all have a plan already, are being built or are **Built**, or one that is **Retired**, offers neither: it has nothing left to plan.

**Plan the whole feature**, on the feature's page, plans every use that still has work to plan, in the order a person would want them. It stays on the page for as long as any use still has a capability with no plan, and says how many: things with nothing planned yet, and things that still have work left to plan. Once every capability has a plan, it goes.

1. [you] **Press Plan this** (or **Plan what's missing**). The use now says **Fleet is planning this…**, so nobody asks twice.
2. [fleet] **Fleet proposes the work.** One to three pieces of work, in the order to build them. Each says **What it delivers** and **Done when**: one sentence you could check on the running product. Under each are the **Plans inside**, a title and a sentence each. Fleet may ask up to two questions first.
3. [you] **Adjust and confirm.** When the proposal is ready the use says **A plan waits on you**. Change any words, remove a piece of work or a plan you do not want, then press **Confirm the plan**. Nothing is built until each plan is ready. The pieces of work and plans this creates are assigned to you, except any that someone else already took.
4. [fleet] **Fleet writes each plan.** Each plan is written out in full and designed. The questions this raises, and any screen design to approve, come to the [Cockpit](guides/daily/cockpit). Every piece of work starts by itself: there is nothing to press.
5. [fleet] **Agents build it.** Each plan is built and then checked by a second agent before it merges, like any other change. The use's state moves on as the plans do.
6. [you] **Check the result.** When a piece of work is done, try it: its **Done when** says what to look for.

What the states on a use mean, from **Not built** to **Built**, is in [Features, uses and capabilities](knowledge-base/feature-areas).

## Add more later

A feature keeps growing after it is added. There are two ways in.

- **From the feature's page.** **+ Add something this feature should do**, under its uses, adds a use: a name of a few words with a verb first, and one sentence. Press **Draft it**; Fleet rewords it to match the page and checks it does not repeat a use the feature already has. Check it and press **Add it**, or **Add it and start planning**. Once Fleet has written it into your repository it joins the list. After **Add it** it reads **Not built** with a **Plan this** button, and the page that confirms the addition says it waits for **Plan this**. After **Add it and start planning** Fleet starts planning it by itself: the use says **Fleet is planning this…** and you do not press anything.
- **From anywhere, with Feature request.** Press **Feature request** at the foot of the sidebar and say what the product should let people do. Fleet first asks **Where does this go?**: inside an existing use, as a new thing an existing feature does, as a new feature, or not a feature at all because it is a bug or a small change. See [File a feature request, a bug or a task](guides/daily/file-work).

A use that has grown too big, so that it needs its own brief or its own owner, is better added as a new feature. Not sure whether your idea is a feature, a use or a capability? [Which one is it](knowledge-base/feature-areas) answers that, and how to name a use.

## Write the brief of a feature that has none

A feature added before briefs existed may have no brief, or its capabilities may not be sorted into uses yet. It is still listed on the **Features** page like any other. Its page still lists what it does, row by row, and offers **Write the brief**.

1. [you] **Press Write the brief.** It is at the top of the feature's page. The page then says **Fleet is drafting the brief**, so nobody asks twice.
2. [fleet] **Fleet drafts the brief.** It writes the summary, the problem, an example and what the feature is not, and sorts the capabilities the feature already has into a few uses. It only groups them: it never rewords, renumbers or drops one.
3. [you] **Check the brief.** It is the same screen as for a new feature. Click any text to change it. Each capability shows under its use with **Move to**, so you can put it in another use. **Ask for changes** sends Fleet a note and it drafts again.
4. [you] **Press Save the brief.** Fleet saves it into the feature's page in your repository by itself, as one reviewed change. Each use then offers **Plan this**.

On a feature with no uses yet, **+ Add something this feature should do** asks for the brief too: give the new thing a name and a sentence, and Fleet drafts the brief with it as one of the uses.

## Find what waits on you

Everything a feature's work is waiting on you for is one click from the feature.

- **On the Features list**, a feature's row says **N waiting on you**.
- **On the feature's header**, **Waiting on you** names up to three pieces of work or plans, each with its number of questions. Each opens that piece of work's or plan's own page, where you answer the questions. **+N more** goes to the full list.
- **On the Overview**, the **Waiting on you** section lists every one, each marked **Plan** or **Piece of work**, with how many questions it has.
- **Under each use**, a line such as "3 questions across 2 plans" leads to the same place.

These are the same questions the [Cockpit](guides/daily/cockpit) holds, narrowed to this feature, so the two counts always agree. A new feature or a plan you asked for also waits on you in the Cockpit, named "New feature: …" or "Plan: …", and opening it lands on the screen where you check it.
